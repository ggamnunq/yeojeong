## 프사 · 프사 스택 규칙 (v3)

- **프사:** 카카오 프사가 있으면 그 사진, 없으면 서비스 기본 유저 이미지를 쓴다. 로파이에서는 사진을 진한 회색 원(#6B7280), 기본 이미지를 연한 회색 원(#E5E7EB) + 사람 아이콘(Icons8 `user`)으로 그렸다. 샘플은 준용·민지가 사진, 태현·수빈이 기본 이미지다. `+N` 데모용으로 하은(사진)과 지호(기본)를 추가했다. 결제 행 왼쪽 결제자 아바타와 멤버 목록·정산 행 등 모든 아바타가 이 규칙을 따른다.
- **공동 결제 표시:** "공동 n명" 태그를 없애고 **부담 인원 프사 스택**으로 바꿨다. 전원과 일부는 스택의 인원 수로만 구분한다. 개인은 `개인 🔒` 태그, 미확정은 점선 `미확정` 태그를 그대로 쓴다.
- **스택 스펙:**

| 항목 | 값 |
|---|---|
| 지름 | 행 20 · 상세 시트 24 · 부담 인원 토글 48 |
| 겹침 | −6 (시트 −7) |
| 테두리 | 흰색 1.5, 바깥쪽 |
| 최대 표시 | 4개, 넘으면 "+N" 원 (예: 6명 → 4 + "+2") |
| 정렬 | **나 먼저 → 나머지는 가입 순** (앞쪽이 위에 겹침) |
| 나 | 진한 테두리(#111827) 2 |
| 나간 멤버 | 흐리게(불투명도 35%) + "나간 멤버" 태그 |

정렬을 "나 먼저"로 정한 근거: 스택이 답해야 하는 질문은 "누가 나눠 내나, **나도 포함인가**"다. 결제자는 행 왼쪽 아바타와 "시각 · 결제자" 텍스트로 이미 보이므로 스택에서 결제자를 또 앞세울 필요가 없다.
- **부담 인원 토글(상세 시트):** 칩 대신 48px 프사 4개를 쓴다. 선택은 진한 테두리 + 체크 배지, 해제는 흐리게 표시하고, 아래에 이름을 둔다. 토글하면 인당 금액이 바로 바뀐다.

## 분담 변경 플로우 (I) — 변경 가능 조건

- **변경할 수 있는 사람:** 결제자 본인만. 여정 **진행 중**에만 바꿀 수 있다.
- **공동 → 개인 (WF-31 → 32 → 33 / 34):** 결제자가 상세에서 [개인]을 고른다. 이미 그룹에 공개된 건이라 확인 다이얼로그(제목 + 한 줄 + 버튼 2개)를 거친다. 바꾸면 내 리스트에는 `개인 🔒`으로 남고 토스트가 뜬다. 다른 멤버 리스트와 정산에서는 사라지고 정산은 다시 계산된다.
- **개인 → 공동 (WF-35):** [공동]을 고르고 부담 인원 프사를 토글해 확정하면 공개된다. "공동으로 변경" 버튼 자체가 명시적 승인이라 다이얼로그는 따로 두지 않았다.
- **부담 인원 변경 (WF-36 전원→일부, WF-37 일부→전원):** 프사 토글로 조정하면 인당 금액이 바로 바뀐다. 원 단위 나머지는 결제자가 부담한다("결제자 +N원" 라벨).
- **결제자가 아닌 멤버 (WF-38):** 읽기 전용이다. 결제자·부담 스택·인당 금액만 보이고 변경 버튼은 없다. **"변경 요청" 기능은 넣지 않았다**(추후 과제).
- **종료 후 (WF-39):** 정산이 확정되면 모든 결제를 잠근다. 결제자도 바꿀 수 없다("변경 불가").
- **변경 이력:** 공동 결제가 바뀌면 행과 상세에 `변경됨` 태그만 붙인다(WF-34·38). 이력 리스트 화면은 추후 과제로, 상세의 `변경됨`을 누르면 열리는 방식을 생각하고 있다.
- I행은 **분기 시나리오**(11.13 21:00)다. F의 정산 수치는 "변경 없음" 기본 시나리오 기준이다.

## TODO 결정 사항과 근거

1. **하단 네비 = 3탭 (결제내역 / 현황 / 여정 정보).** 노션은 "결제이력+현황"을 한 항목으로 적었지만, 진행 중 결제내역은 리스트/타임라인 토글이 필요해서 한 탭에 현황까지 넣으면 토글이 2단으로 겹친다. 진행 중 가장 자주 쓰는 두 화면을 한 번에 탭으로 열 수 있게 분리했다. 상태별 변형: **시작 전**에는 결제내역·현황 탭을 잠그고(자물쇠, 반투명) 여정 정보 탭이 기본, **종료 후**에는 2번 탭이 "현황 → 정산"으로 바뀌고 기본 진입 탭이 된다(탭 위치는 그대로).
2. **결제내역은 두 형태 모두 제공.** 리스트(기본) = 최신순·날짜 구분·확인/검토용. 타임라인 = 하루 단위 시간순(위→아래)·여행 흐름 회고용(Day 칩으로 날짜 이동, 끝에 "지금"). 역할이 달라서 둘 다 둔다. **전환은 결제내역 탭 상단의 세그먼트 토글 [리스트|타임라인]**으로 하고 마지막 선택을 기억한다. v2에서는 필터를 빼고 토글을 전체 폭으로 넓혔다(미확정만 보기는 배너로 들어간다).
3. **새로 불러온 결제 = "미확정·비공개".** 결제자만 보이고(기획 원칙: 금융 원본은 본인만, 공개는 명시적 승인 후), 결제내역 상단 점선 배너("확인 필요 n건 ›")로 알린다. 결제 행을 누르면 바텀시트가 열리고 [개인|공동]을 고른 뒤 확정한다. 공동이면 부담 인원 프사 토글(기본 전원, 탭해 해제 → 인당 금액 즉시 재계산, v3)이 나온다. 확정 = 그룹 공개 + 정산 반영이다. 확정한 뒤에도 결제자는 진행 중에 다시 열어 고칠 수 있다(I 분담 변경).
4. **오버레이 역할 분담.** 그룹원 = 헤더 ≡ → 좌측 사이드 패널(햄버거 관례, 인원이 늘어도 스크롤 가능). 결제 상세 = 바텀시트(목록 맥락 유지). 되돌릴 수 없는 행동(시작·종료·삭제) = 중앙 다이얼로그. 그룹 전환 = 헤더 아래 드롭다운.
5. **예산 = 공동 지출 기준 금액 하나.** 개인 결제는 비공개라 그룹 예산에 합칠 수 없다. 현황에는 "쓴 금액 / 예산"과 바 하나만 둔다(노션 메모: 설정 + 초과 여부 정도). v1의 일정 50% 세로선·남은 예산·%는 v2에서 뺐다.
6. **권한: 여정 시작 · 수동 종료 · 그룹 삭제(시작 전에만) · 강퇴 = 그룹장만.** 멤버에게는 해당 버튼을 숨기고 안내 문구만 보여준다. 그룹장이 나가면 가입 순으로 승계한다(노션). 이 내용은 패널 하단에 표시한다.
7. **종료 시 남은 미확정 결제는 개인(비공개)으로 처리**한다. v3에서 엣지케이스로 다시 보강해, 수동 종료 다이얼로그 본문에 "미확정 2건은 개인으로 처리돼요" 한 줄과 자동 종료 시각 라벨을 넣었다.
8. **정산 표시 방식.** 멤버별로 결제 합계 / 최종 부담(부담 인원 반영) / 정산 = 결제 − 부담을 보여주고, **+받을 돈 / −보낼 돈**으로 표기한다. N빵(총액÷인원) 금액을 함께 보여 "택시처럼 일부만 나눈 결제 때문에 N빵과 다르다"는 점을 납득시킨다. 송금 기능은 없다(노션). v2에서는 "실제 송금 없음" 안내문과 송금 경로 제안을 화면에서 뺐다. 송금 버튼이 아예 없으니 안내가 없어도 오해할 여지가 적다고 판단했다.
9. **멤버별 결제 내역.** 공동 결제는 전부 목록으로 보여주고 최종 부담 계산 근거도 같이 보여준다(정산 추적 가능성). 다른 사람의 개인 결제는 "개인 결제 n건 · 비공개"로 건수만 보여준다. 본인 이름을 누를 때만 개인 결제 목록까지 보인다. v2에서는 부담 계산 박스를 뺐다.
10. **지갑 연동 표현 = "토스로 불러오기" 단일 진입.** 노션의 "토스 증권 or 페이먼츠 API"를 사용자에게는 토스 한 곳으로만 보여준다(은행·카드사를 하나씩 고르지 않음). 흐름은 안내(범위·비공개·조회 전용) → 토스 외부 인증(우리 쪽은 대기·복귀 상태만 정의) → 돌려받은 계좌·카드 체크 선택 → 완료다. 가입(WF-05~08)과 지갑 추가(WF-28 → WF-06~08)가 같은 화면을 함께 쓴다.
11. **환율 = 여정 단위 설정.** 정산은 모든 멤버에게 같아야 하므로 그룹장만 바꿀 수 있다. 기본값은 결제 시점 매매기준율이고, 대안으로 카드사 청구 환율(확정 시 교체)과 고정 환율 직접 입력을 둔다. 기준 통화는 KRW 고정이고 여행 통화는 장소에서 자동으로 정해진다. 환율 옆에는 항상 갱신 시각과 출처를 표시한다. 결제 행·상세에는 원화 환산(굵게)과 원통화를 함께 보여준다.
12. **지갑·마이페이지 = 하단 네비 없는 서브페이지.** 노션은 네비를 "현재 여정 정보"로 정의했고, 두 화면은 계정 단위라서 네비를 뺐다. 마이페이지에는 닉네임·지갑 요약·로그아웃만 두고(탈퇴 없음), "그 외 TODO"는 이용약관·개인정보 처리방침·버전 정보로 최소화했다.
13. **기타.** 여정 0개일 때 헤더는 그룹명 대신 "여정" 워드마크를 보여주고 ≡·▾는 없다. 여정 생성 입력 항목은 노션의 4개뿐이고 통화는 장소에서 자동으로 정해진다. 닉네임은 카카오 이름으로 미리 채운다. 약관에 "금융거래정보 조회"를 필수로 넣었다. 초대코드 형식은 영문·숫자 6자리다. 지출 카테고리 UI는 넣지 않았다(범위 밖).

## 파일 / 재실행

- `icons.js` — Icons8 PNG(base64) `ICG`(6B7280) / `ICK`(111827) 각 55개. 원본 다운로드·컨택트 시트는 `_icons/`.
- `lib.js` — 공통 부품(v3). v1·v2 백업은 `_lib_v1_backup.js` · `_lib_v2_backup.js`. v3에서 추가한 것: `PROFILE` `ME` `orderMembers` `avatar`(프사 규칙) `stack`(프사 스택) `avatarToggle` `flagTag` `payMark` `sub`(중첩 섹션) `PLACE` `gpos` `findWF` `place` `removeNamed`. 기존 부품: `screen` `statusBar` `appHeader` `subHeader` `bottomNav` `body` `btn` `tag` `avatar` `input` `card` `kv` `segmented` `bar` `checkbox` `radio` `placeholder` `payRow` `dateHeader` `payTop` `compactBanner` `payListContent` `tripInfoCard` `memberRows` `inviteStrip` `dim` `sheet` `dialog` `toast` `note` `rowTitle` `clean`, 샘플 데이터 `PAY_D1/PAY_D2`, 그리드 `BAND_Y` `COL` `FRAME_DY`.
- 행 스크립트(v3): `12_rowI.js`(분담 변경) `13_rowJ.js`(엣지케이스 + 규칙표 + J 섹션 높이 맞춤)를 추가했다. 기존 스크립트: `01_rowA1.js` `02_rowA2.js` `03_rowB.js` `04_rowC.js` `05_rowD.js` `06_rowE1.js` `07_rowE2.js` `08_rowE3.js` `09_rowF.js` `10_rowGH.js` `11_header.js`(섹션 헤더 + 섹션 크기 맞춤)
- v3의 `screen()`은 같은 WF 프레임이 있으면 **노드를 재사용**한다(자식만 비우고 다시 그림 → 프레임 ID 유지). 위치와 부모는 `PLACE` 표(WF 번호 → 중첩 섹션·순번)로 정해지므로 스크립트 안의 좌표 인자는 무시된다. `06_rowE1.js`는 WF-18(24:7451)을 행 노드까지 유지한 채 고친다. `11_header.js`는 맨 마지막에 실행해야 04 크기가 맞고 `sections`가 기록된다.

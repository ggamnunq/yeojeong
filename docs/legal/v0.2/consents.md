# 동의 항목 정의 — 0.2 릴리스 (개발용)

> 작성 2026-10-30 · 릴리스 폴더 `v0.2/` · **문서마다 버전을 따로 매긴다**(이 표의 "문서 버전" 열). 시행은 두 갈래: 개인정보 문서(동의서·카드 내역 조회 동의서·처리방침·처리위탁 고지) = **게시일 즉시**(`{{게시일}}`), 서비스 이용약관 = **게시일 + 7일**(`{{게시일+7}}` — 2026-10-30 게시면 2026-11-06).
> 0.1 [../v0.1/consents.md](../v0.1/consents.md)에서 `TOS`·`PRIVACY`를 0.2로 올리고 **`CARD_IMPORT` 0.1을 신설**한다. `AGE14`는 0.1 그대로. 2절 WF-04 화면·3절 재동의 화면·4절 고지 문서 링크·6절 가입 동의 철회는 0.1과 같다.
> **재동의 판단 규칙(0.x)**: MAJOR가 늘 0이라 번호로 판단하지 않는다. 버전 행마다 아래 "재동의 필요" 표시로 판단한다(개발 쪽 규칙 변경 — README 6절 #3).

- 마이그레이션: `consent_documents`에 `TOS` `0.2`(`effective_at = {{게시일+7}} 00:00 KST`), `PRIVACY` `0.2`(`effective_at` = 게시 시각), `CARD_IMPORT` `0.1`(`isDraft = false`, `effective_at` = 게시 시각) 행을 **추가**한다. 0.1 행과 `CARD_IMPORT` `0.1-draft` 행은 고치지 않는다.
- doc_hash = 이 폴더 게시본 파일(자리표시를 채운 뒤)의 SHA-256. `CARD_IMPORT`는 「카드 내역 조회 동의서.md」 파일 해시. **`sync-legal.mjs`의 해시 칸 갱신은 지금 `TOS|PRIVACY|AGE14` 행만 고치므로 `CARD_IMPORT` 행을 더하고, `AGE14`에 TOS 0.2 해시가 들어가지 않게** 해야 한다(README 6절 #1).
- `summary`(운영 기록용):
  - `TOS 0.2`: `서비스 이용약관 0.2 — 카드 내역 불러오기 시범 운영 조항(제12조의2) 신설, 정의·서비스 내용·면책에 카드사·조회 업체 추가. 카드 기능 미이용 회원 불리 변경 없음, 재동의 없음`
  - `PRIVACY 0.2`: `개인정보 수집·이용 동의서 0.2 — 로그인 세션 보유 기간 정정(3개월 → 최대 30일), 만 14세 확인 값과 동의 기록 보관 관계 명시, 카드 기능은 별도 동의서 안내. 사실 정정, 재동의 없음`
  - `CARD_IMPORT 0.1`: `카드 내역 조회 동의서 0.1 — 시범 운영(허용 회원) 개인(신용)정보 수집·이용 동의 신설, 헥토데이터(CODEF) 위탁`
- **판정**:
  - `TOS` 0.1·`PRIVACY` 0.1에 유효하게 동의한 회원은 0.2 시행 뒤에도 유효한 동의로 본다 — `403 CONSENT_REQUIRED`·재동의 화면을 띄우지 않는다.
  - `PRIVACY`는 게시 시각부터 0.2가 현행(그 뒤 가입자 `version = 0.2`). `TOS`는 `{{게시일+7}}` 전까지 0.1이 현행이고 그 사이 가입자는 `TOS` 0.1·`PRIVACY` 0.2에 동의한다.
  - `CARD_IMPORT`: 카드 내역 조회 API(`POST /api/card-import/fetch` 등)에서 현재 시행 버전의 유효 동의를 검사한다(없으면 `403 CONSENT_REQUIRED { missing: ["CARD_IMPORT"] }`). `isDraft` 문서(`0.1-draft`)로 받은 동의는 유효 동의로 치지 않는다.
- 고지 문서(처리방침 0.2·처리위탁 고지 0.2)는 동의 대상이 아니라 이 표에 행이 없다. 오픈소스 고지는 0.1 그대로.
- **결제 앱 거래 내역 파일 가져오기(위챗페이, 지갑 항목 `source = FILE_IMPORT`, 제공처 `WECHAT`)는 동의 ID를 두지 않는다 — 이 표에 변화 없음.** 회원이 직접 올린 본인 파일에서 고른 결제를 지갑에 기록하는 것이라 수동 입력과 같은 성격(처리 근거 계약 이행)으로 보고, 파일은 브라우저 안에서만 읽어 서버·외부 업체로 보내지 않는다. 진입 시 동의 화면·`403 CONSENT_REQUIRED` 검사 없음. `PRIVACY` 0.2 동의서 문구·해시도 바뀌지 않는다(README 3-3절, 8절 R-42).

## 2. HF-51 카드 내역 불러오기 — 시작 전 확인

| 요소 | 내용 |
|---|---|
| 노출 조건 | 회원에게 카드 내역 불러오기 이용 권한이 있을 때만 진입점이 보인다(관리자 페이지 "카드 불러오기 권한" 탭에서 운영자가 부여·회수) |
| 동의 행 | `[필수] 카드 내역 조회 동의` + `›` → `/consents/CARD_IMPORT`(전문 제목 "[필수] 개인(신용)정보 수집·이용 동의 (카드 내역 조회)") |
| 기본 체크 | 해제. "계속"은 체크 전 비활성 |
| 기억 | 현재 시행 버전 `CARD_IMPORT` 유효 동의가 있으면 동의 행을 숨기고 사실 3줄 + "계속"만 보인다. 철회했거나 "재동의 필요" 버전이 시행되면 다시 보인다 |
| 저장 | 체크 후 "계속" → UserConsent 1행(`consent_type = CARD_IMPORT`, `version = 0.1`, `screen = HF-51`, `method = INDIVIDUAL`). 저장에 성공해야 다음 화면으로 간다 |
| 거부 | 텍스트 링크 "직접 추가할게요" → 결제 직접 입력. 다른 기능 제한 없음 |

## 3. 철회 처리 (0.2 릴리스)

| ID | 철회 화면 | 서버 처리 |
|---|---|---|
| `TOS`, `PRIVACY`, `AGE14` | 0.1과 같음(탈퇴) | 0.1과 같음 |
| `CARD_IMPORT` | 마이페이지 > 동의 관리(HF-58) "철회". 기능이 꺼져 있거나 이용 권한이 회수되어도 철회는 늘 가능 | `withdrawn_at`, `withdraw_channel = HF-58`. 이후 불러오기 전에 HF-51에서 다시 동의. **이미 저장한 지갑 항목(`source = CARD_IMPORT`)은 유지**(회원이 고른 결제 — README 8절 R-37). 탈퇴 시 `ACCOUNT_DELETED` |

- 이용 권한 회수는 동의 철회가 아니다. 권한을 회수해도 `CARD_IMPORT` 동의 행은 그대로 두고(다시 권한을 받으면 그 동의가 유효), 저장한 지갑 항목도 그대로 둔다.

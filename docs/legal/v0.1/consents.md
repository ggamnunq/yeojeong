# 동의 항목 정의 v0.1 (개발용)

> 문서 버전 0.1 · 작성 2026-10-29 · 시행일 `2026-10-30` · (2026-10-30 재번호: 게시 당시 이름 "1.0" → **0.1**. MVP 기간은 0.x로 매긴다 — 0.x에서는 MAJOR가 늘 0이라 **번호로 재동의를 판단하지 않고 아래 표의 "재동의 필요" 열로 판단**한다)
> 0.1 정식 발행에서 받는 동의 항목의 단일 기준이다. 저장 구조(`UserConsent`·`ConsentDocument`), append-only 규칙, 판정(현재 시행 버전의 가장 최근 행), 철회 필드는 상위 폴더 [../consents.md](../consents.md) 4절과 같고 이 문서는 바꾸지 않는다.

- 게시 당시(#58) 해시: TOS·AGE14 = `97b15008160a8e381efb66222f27487b316d1925c01e6fe54c114cc1aabd7c58`, PRIVACY = `ad74dea6c6372da76c72bdd546b389e66815e4da6af15ed66cde1addfe33cfd6`. 재번호로 각 파일 3행이 "버전 1.0" → "버전 0.1"로 바뀌어 해시가 달라진다 — 개발 세션이 `legal:sync`로 다시 계산하고, 이미 저장된 `user_consents`·`consent_documents`의 `1.0` 행을 `0.1`로 옮길지(또는 `1.0` = `0.1` 별칭으로 둘지) 정한다(README 6절 #26).
- `change_type = MAJOR`, 재동의 필요: `0.1-draft`(isDraft)로 받은 동의는 법적 유효 동의가 아니므로 0.1 발행 시 기존 사용자 전원에게 재동의(FR-107)를 띄운다(출시 게이트 L-1).
- `summary`(운영 기록용): `정식 약관 0.1 시행 — 수동 결제·지갑·공동 결제 공개 범위 반영, 연동·카드 불러오기·마케팅 제외`.
- `AGE14`는 별도 전문이 없다. `doc_hash`는 근거 조항이 있는 이용약관 파일의 해시를 그대로 쓰는 것을 제안한다(개발 세션 확정).
- 버전 규칙(개발 세션 확정, 2026-10-30 0.x로 바꿈): `version` = 문서 버전 `0.1`(UserConsent·ConsentDocument 공통), 시행일은 `ConsentDocument.effectiveAt`에 따로 둔다. 다음 개정은 문서마다 `0.2`, `0.3` …으로 올리고, **재동의 여부는 번호가 아니라 버전 행의 "재동의 필요" 표시**로 정한다(0.x에서는 MAJOR가 늘 0).

## 2. WF-04 약관 동의 (가입 시)

| 행 | 화면 표시 | ID | 기본 체크 | `›` 연결 |
|---|---|---|---|---|
| 0 | 전체 동의 | — (1~3행 일괄 토글) | 해제 | — |
| 1 | [필수] 서비스 이용약관 | `TOS` | 해제 | `/terms` |
| 2 | [필수] 개인정보 수집·이용 | `PRIVACY` | 해제 | `/consents/PRIVACY` |
| 3 | [필수] 만 14세 이상입니다 | `AGE14` | 해제 | 없음 |

- 선택 항목이 없으므로 행 0의 "(선택 포함)" 표기를 쓰지 않는다.
- "다음"은 1~3행이 모두 체크되어야 활성화된다. 저장 = User + UserConsent 3행(`screen = WF-04`, `method = ALL | INDIVIDUAL`) + Session, 한 트랜잭션.
- 화면 하단에 "개인정보 처리방침"(`/privacy`) 텍스트 링크를 둔다(동의 대상 아님).
- 동의서 전문의 **굵게** 표시 부분은 화면에서 다른 글자보다 크게(20% 이상) 또는 굵게·색으로 구분한다(「개인정보 보호법」 제22조제2항, 시행령 제17조제3항).

## 3. 재동의 (0.1 발행 시)

- 로그인·세션 갱신 때 `TOS`·`PRIVACY`·`AGE14`의 `0.1` 유효 동의가 없으면 `403 CONSENT_REQUIRED { missing, required }` → 재동의 화면(WF-04 구성 재사용, `screen = RECONSENT`).
- 재동의 화면에서 할 수 있는 다른 행동은 로그아웃과 탈퇴뿐이다(약관 제3조제5항). 화면: "로그아웃" 옆 조용한 텍스트 링크 "탈퇴" → WF-59(명세 C-14). 서버는 재동의를 마치지 않은 사용자에게도 `DELETE /api/users/me`를 허용한다(`CONSENT_REQUIRED`로 막지 않음).
- 이미 `0.1`에 유효한 항목은 다시 쓰지 않고, 없는 항목만 새 행으로 append한다.

## 5. 0.1에서 받지 않는 ID

`ConsentDocument`에 0.1 버전을 만들지 않는다. enum 값은 그대로 둔다.

| ID | 상태 | 다시 쓸 때 |
|---|---|---|
| `MARKETING` | 숨김(발송 채널 없음). WF-04 행·WF-30 토글 없음 | 채널 확정 시 동의서 절 신설 + 약관 제22조②·처리방침 개정 |
| `FIN_LINK`·`FIN_PRIVACY`·`THIRD_PARTY` | `features.accountLink = false` — 받지 않음, `/consents/FIN_*` 공개 안 함 | 토스 연동을 켤 때 부속약관·동의서·제3자 제공 동의서 정식판 발행(상위 폴더 초안 기준) + 처리방침·약관 개정 |
| `CARD_IMPORT` | 0.1 범위 밖. `FEATURE_CARD_IMPORT`는 `off` 또는 `allowlist`(운영자 본인 계정)만 허용. 기존 `0.1-draft` 문서는 allowlist 시험용으로만 남는다 | **0.2 릴리스에서 신설** — 별도 문서 「카드 내역 조회 동의서」 0.1, 시범 운영(허용된 회원만). [../v0.2/consents.md](../v0.2/consents.md) |
